NetBird для Home Assistant це незалежна read-only інтеграція для [NetBird](https://netbird.io/), яка працює з NetBird Cloud або явно вказаним self-hosted HTTPS endpoint. Вона показує стан облікового запису, peer-пристроїв і топологію Networks, Resources та Routers. Позначка «підключено» означає зв'язок із Management Service, але **не підтверджує** доступність VPN-з'єднання між двома пристроями.

## Стан проєкту

[Версія `1.0.2`](https://github.com/rodion981/ha-netbird/releases/tag/v1.0.2) виправляє видалення активних Network resources під час очищення peers, перевіряє DNS-відповіді self-hosted сервера безпосередньо перед підключенням і оновлює назви пристроїв та версії peer-клієнтів без зміни ідентифікаторів. Збережено Cloud і self-hosted моніторинг, довіру до власного CA, групову маршрутизацію та адаптивні EN/UK dashboards. Встановлюйте через кастомний репозиторій HACS або вручну; це не означає наявність у стандартному каталозі HACS.

## Можливості

- Один обліковий запис Cloud або self-hosted на запис інтеграції; авторизація через персональний токен доступу (PAT).
- Спільне опитування списку peer-пристроїв кожні 60 секунд; нові пристрої з'являються без перезавантаження.
- Сенсори облікового запису: кількість peer-пристроїв, Networks, ресурсів і маршрутизаторів.
- Стани peer-пристрою: підключення, остання активність, IP-адреса, доступні піри, останній вхід, SSH, ephemeral, завершення терміну входу та потреба в схваленні, якщо поле є в API.
- Необов'язкова діагностика, вимкнена за замовчуванням: IPv6, hostname, DNS label та операційна система.
- Актуальні NetBird **Networks**, Resources і Routers із підсумками мереж та окремими пристроями ресурсів. Застарілі Routes навмисно не підтримуються.
- Підсумки маршрутизації Networks із підтримкою груп та стан **Маршрутизація доступна** для кожного ресурсу без заяв про наскрізну доступність.
- Окреме опитування топології кожні п'ять хвилин із максимум шістьма паралельними вкладеними запитами. Для `N` мереж оновлення використовує `1 + 2N` API-запитів.
- Агрегована діагностика без приватних даних та повідомлення Repairs, якщо очищення застарілого пристрою заблоковане.
- Український і англійський переклади інтерфейсу.

Cloud використовує фіксовану адресу `https://api.netbird.io`. Для self-hosted потрібна явна HTTPS-адреса API, необов'язкова окрема HTTPS-адреса dashboard і, за потреби, PEM-сертифікат CA. HTTP, вимкнення перевірки TLS, URL із path prefix, перенаправлення, mTLS, discovery, MSP/multi-tenant, застарілі Routes, дії запису, метрики трафіку та перевірки VPN-шляху не підтримуються.

## Встановлення

Потрібні Home Assistant `2026.9.3` або новіший і PAT із доступом до облікового запису, peer-пристроїв, Networks, Resources та Routers. Self-hosted сервер має надавати той самий використаний контракт Management API через HTTPS. Home Assistant постачає власний Python; для розробки потрібен Python `3.14.2` або новіший.

### Через кастомний репозиторій HACS

Натисніть кнопку HACS вище або:

1. Відкрийте **HACS > Custom repositories**.
2. Додайте `https://github.com/rodion981/ha-netbird` із типом **Integration**.
3. Відкрийте **NetBird HA Monitor** і натисніть **Download**.
4. Перезапустіть Home Assistant.
5. Відкрийте **Налаштування > Пристрої та служби > Додати інтеграцію**, виберіть **NetBird HA Monitor**, потім Cloud або self-hosted і введіть запитані дані.

Кнопка відкриває HACS; завантаження та налаштування інтеграції виконуються окремо. Якщо HACS не має доступу до репозиторію, встановіть інтеграцію вручну.

### Приклад dashboard

[Український dashboard NetBird](examples/netbird-dashboard.uk.yaml) і [англійська версія](examples/netbird-dashboard.yaml) використовують адаптивний стандартний Sections view з окремими картками Огляду, Пірів, Мереж і Ресурсів. Вони знаходять сутності через інтеграцію та стабільний `netbird_key`, тому не залежать від створених `entity_id` чи назв пристроїв.

1. Створіть порожній dashboard у Home Assistant.
2. Відкрийте **Редактор сирої конфігурації** та вставте YAML із прикладу.

Dashboard демонструє основні лічильники облікового запису, підключення, IP-адресу, час активності, доступність, стани SSH та ephemeral для пірів, місткість мереж і доступність маршрутизації ресурсів. Він використовує адаптивні підсумки замість широких таблиць і показує час у стислому локальному форматі. Відсутні сутності показуються як `—`; невідомі й недоступні значення відрізняються від `false` та нуля. Сторонні картки не потрібні.

Сторінки пристроїв Home Assistant містять посилання на dashboard лише коли його origin відомий: `/peers` для облікового запису, `/peer?id=<peer-id>`, `/network?id=<network-id>` або `/network?id=<network-id>&resource=<resource-id>`. Cloud використовує `app.netbird.io`; self-hosted використовує лише окремо введену адресу dashboard і ніколи не виводить її з API URL. Ідентифікатори кодуються окремо. Ці deep links працюють за принципом best effort, оскільки маршрути dashboard не є стабільним API-контрактом NetBird.

### Вручну та оновлення

Скопіюйте `custom_components/netbird` до каталогу конфігурації Home Assistant за шляхом `custom_components/netbird`. Перезапустіть Home Assistant і додайте **NetBird HA Monitor** через **Пристрої та служби**. Для ручного оновлення зробіть резервну копію конфігурації, замініть цей каталог файлами вибраної версії та перезапустіть Home Assistant. Для оновлення через HACS скористайтеся його звичайним механізмом і перезапустіть Home Assistant.

## Налаштування та ротація PAT

Форма перевіряє PAT, а ID облікового запису залишається стабільною ідентичністю. Для self-hosted до збереження також перевіряється повний контракт account, peers, networks, resources і routers. ID облікового запису запобігає дублюванню між типами розгортання. Токен іншого облікового запису не замінить поточний.

Створіть новий PAT для того самого облікового запису. Reauthentication змінює лише PAT. **Reconfigure** замінює Cloud PAT або атомарно оновлює self-hosted API URL, необов'язковий dashboard URL, PAT і CA після повної перевірки. Тип розгортання не можна перемкнути в наявному записі. Після перевірки відкличте старий PAT. HTTP 401 запускає повторну авторизацію. HTTP 403 означає нестачу дозволів; звичайний HTTP 404 не доводить завершення терміну PAT.

## Оновлення даних і доступність

Інтеграція опитує peer-пристрої кожні 60 секунд через спільний координатор. Окремий координатор опитує Networks кожні 300 секунд. Після списку мереж Resources і Routers завантажуються зі спільним лімітом шість паралельних запитів. Помилка вкладеної секції впливає лише на цю секцію мережі; помилка топології не впливає на peer-стани.

Connected routing peers визначає ввімкнені routers, адресовані конкретному peer або групі peers, усуває дублікати peers із кількох шляхів і враховує їхній стан з'єднання з Management Service. Якщо дані router, групи, peer або з'єднання неповні, лічильник стає недоступним замість заниженого значення.

Маршрутизація доступна має стан `on`, коли ввімкнений ресурс має хоча б один визначений підключений routing peer. Стан `off` означає, що ресурс вимкнений, немає ввімкнених routers або всі повністю визначені routing peers явно відключені. За неповних даних сутність недоступна, крім випадку, коли інший повний шлях уже доводить `on`. Це доказ конфігурації маршрутизації та з'єднання з Management Service, а не перевірка ACL, DNS, трафіку чи наскрізного VPN-шляху.

Після невдалого опитування сутності координатора стають недоступними, щоб не показувати старі дані як поточні. Peer-пристрій, відсутній в успішному списку, також стає недоступним. Якщо необов'язкове логічне поле відсутнє, відповідний бінарний сенсор недоступний, а не вимкнений. Некоректний або відсутній час останньої активності не дає значення. Поле підключення не перевіряє VPN-маршрути, DNS, ACL чи трафік між пристроями.

Після 10 послідовних **успішних** знімків без peer-пристрою інтеграція видаляє належні їй записи реєстру. Помилки не збільшують лічильник; повернення пристрою його скидає. Лічильник зберігається лише в пам'яті, тому перезавантаження може відкласти очищення. Якщо належність пристрою або сутностей неоднозначна, видалення блокується і з'являється повідомлення Repairs. Історія, вже записана Home Assistant Recorder, зберігається за його правилами.

## Приватність і діагностика

Self-hosted hostname повторно перевіряється під час завантаження, а всі DNS-адреси нового з’єднання перевіряються до відкриття сокета. Приватні LAN та IPv6 ULA адреси підтримуються. Cloud використовує спільну HTTP session Home Assistant; self-hosted має окрему session із захищеним resolver, яка закривається після невдалого setup або unload.

PAT і власний CA зберігаються в записі інтеграції Home Assistant; PAT надсилається лише налаштованому API origin для read-only запитів. Кожен запит перевіряє HTTPS, має 10-секундний timeout і не виконує redirect із заголовком авторизації. Захищайте резервні копії та не передавайте PAT. Увімкнені сутності IP, hostname, DNS label, операційної системи й адреси ресурсу доступні Recorder та можуть потрапити в історію і резервні копії. Інтеграція не створює окремої бази. Діагностика містить лише тип розгортання, ознаку власного CA, версії, стани/класи помилок і агреговані лічильники; токенів, ID, імен, адрес, URL, сертифікатів, redirect targets і сирих відповідей немає.

| Симптом | Що перевірити |
| --- | --- |
| Помилка авторизації | Замініть PAT того самого облікового запису через **Reconfigure** або повторну авторизацію. |
| Недостатньо дозволів | Перевірте доступ PAT до облікового запису; HTTP 403 не означає автоматично завершення терміну дії. |
| Немає з'єднання або некоректна відповідь | Для Cloud перевірте `https://api.netbird.io` і стан сервісу. Для self-hosted перевірте кінцевий HTTPS API origin, DNS, ланцюжок сертифікатів, дозволи PAT і потрібні endpoint-и. Redirect відхиляється. |
| Peer недоступний | Перевірте останнє успішне опитування та наявність peer у NetBird. Окремі сенсори можуть бути недоступними через відсутні поля. |
| Застарілий peer залишається | Дочекайтеся 10 успішних знімків без нього; перевірте **Налаштування > Виправлення**. |
| Підключено, але трафік не проходить | Перевірте клієнти NetBird, маршрути, DNS, політики й кінцевий пристрій. |

Щоб видалити інтеграцію, видаліть її запис у **Налаштування > Пристрої та служби > NetBird HA Monitor**. Потім видаліть інсталяцію HACS або каталог `custom_components/netbird` та перезапустіть Home Assistant. Непотрібний PAT відкличте окремо в NetBird. Для історії Home Assistant і резервних копій діють окремі правила зберігання.

## API та обмеження

Інтеграція читає `GET /api/accounts`, `GET /api/peers`, `GET /api/networks`, `GET /api/networks/{id}/resources` і `GET /api/networks/{id}/routers` за фіксованою Cloud-адресою або нормалізованим self-hosted HTTPS origin. Застарілий `/api/routes` не викликається, окремий запит груп не додається. Self-hosted сумісність визначається можливостями: setup перевіряє всі використані форми endpoint-ів, а не вгадує підтримку за версією сервера. Обов'язкові ID і поля топології перевіряються; необов'язкові peer-поля та поля груп можуть бути відсутніми або `null`. Після HTTP 429 або серверної помилки інтеграція чекає наступного опитування. Захищений [Cloud live API contract run](https://github.com/rodion981/ha-netbird/actions/runs/36159603786/job/108170984157) від 25 вересня 2026 року є лише точковим Cloud-доказом форми API. Для self-hosted релізу потрібно окремо зафіксувати версію NetBird, тип HTTPS-розгортання, setup/reload/poll, reauth, reconfigure, помилку redirect/TLS і результат private CA без збереження приватних значень.

Повідомляйте про відтворювані помилки через [GitHub Issues](https://github.com/rodion981/ha-netbird/issues) без токенів, приватних адрес, сирих відповідей або неочищеної діагностики.
