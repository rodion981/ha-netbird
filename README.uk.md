NetBird для Home Assistant це незалежна кастомна інтеграція для моніторингу [NetBird Cloud](https://netbird.io/). Вона лише читає Management API та показує стан облікового запису, peer-пристроїв і актуальну топологію Networks, Resources та Routers. Позначка «підключено» означає зв'язок із Management Service, але **не підтверджує** доступність VPN-з'єднання між двома пристроями.

## Стан проєкту

Версія `0.2.0` додає корисну діагностику peer-пристроїв і актуальну топологію NetBird Networks. Встановлюйте її через кастомний репозиторій HACS або вручну. Кнопка HACS відкриває цей репозиторій; вона не означає, що інтеграція є в стандартному каталозі HACS.

## Можливості

- Один обліковий запис Cloud на запис інтеграції; авторизація через персональний токен доступу (PAT).
- Спільне опитування списку peer-пристроїв кожні 60 секунд; нові пристрої з'являються без перезавантаження.
- Сенсори облікового запису: кількість peer-пристроїв, Networks, ресурсів і маршрутизаторів.
- Стани peer-пристрою: підключення, остання активність, IP-адреса, доступні піри, останній вхід, SSH, ephemeral, завершення терміну входу та потреба в схваленні, якщо поле є в API.
- Необов'язкова діагностика, вимкнена за замовчуванням: IPv6, hostname, DNS label та операційна система.
- Актуальні NetBird **Networks**, Resources і Routers із підсумками мереж та окремими пристроями ресурсів. Застарілі Routes навмисно не підтримуються.
- Окреме опитування топології кожні п'ять хвилин із максимум шістьма паралельними вкладеними запитами. Для `N` мереж оновлення використовує `1 + 2N` API-запитів.
- Агрегована діагностика без приватних даних та повідомлення Repairs, якщо очищення застарілого пристрою заблоковане.
- Український і англійський переклади інтерфейсу.

Підтримується лише NetBird Cloud за фіксованою адресою `https://api.netbird.io`. Самостійно розгорнуті сервери, застарілі Routes, дії запису, метрики трафіку та перевірки VPN-маршруту до цього релізу не входять.

## Встановлення

Потрібні Home Assistant `2026.9.3` або новіший і Cloud PAT із доступом до облікового запису, peer-пристроїв, Networks, Resources та Routers. Home Assistant постачає власний Python; для розробки потрібен Python `3.14.2` або новіший.

### Через кастомний репозиторій HACS

Натисніть кнопку HACS вище або:

1. Відкрийте **HACS > Custom repositories**.
2. Додайте `https://github.com/rodion981/ha-netbird` із типом **Integration**.
3. Відкрийте **NetBird** і натисніть **Download**.
4. Перезапустіть Home Assistant.
5. Відкрийте **Налаштування > Пристрої та служби > Додати інтеграцію**, виберіть **NetBird** і введіть PAT.

Кнопка відкриває HACS; завантаження та налаштування інтеграції виконуються окремо. Якщо HACS не має доступу до репозиторію, встановіть інтеграцію вручну.

### Приклад dashboard

[Універсальний dashboard NetBird](examples/netbird-dashboard.yaml) складається з однієї стандартної Markdown-картки. Він знаходить сутності через інтеграцію та стабільний `netbird_key`, тому не залежить від створених `entity_id` чи назв пристроїв.

1. Створіть порожній dashboard у Home Assistant.
2. Відкрийте **Редактор сирої конфігурації** та вставте YAML із прикладу.

Dashboard показує загальні лічильники, корисні дані peer-пристроїв, Networks і мережеві ресурси. Відсутні сутності показуються як `—`; невідомі й недоступні значення відрізняються від `false` та нуля. Сторонні картки не потрібні.

### Вручну та оновлення

Скопіюйте `custom_components/netbird` до каталогу конфігурації Home Assistant за шляхом `custom_components/netbird`. Перезапустіть Home Assistant і додайте **NetBird** через **Пристрої та служби**. Для ручного оновлення зробіть резервну копію конфігурації, замініть цей каталог файлами вибраної версії та перезапустіть Home Assistant. Для оновлення через HACS скористайтеся його звичайним механізмом і перезапустіть Home Assistant.

## Налаштування та ротація PAT

Форма перевіряє PAT через Cloud API облікового запису та peer-пристроїв. ID облікового запису запобігає дублюванню записів. Токен іншого облікового запису не замінить поточний.

Створіть новий PAT для того самого облікового запису. У записі NetBird виберіть **Reconfigure**. Home Assistant перевірить новий PAT до збереження та перезавантаження. Переконайтеся, що інтеграція працює, тоді відкличте старий PAT. HTTP 401 запускає повторну авторизацію. HTTP 403 означає нестачу дозволів; звичайний HTTP 404 не вважається доказом завершення терміну дії PAT.

## Оновлення даних і доступність

Інтеграція опитує peer-пристрої кожні 60 секунд через спільний координатор. Окремий координатор опитує Networks кожні 300 секунд. Після списку мереж Resources і Routers завантажуються зі спільним лімітом шість паралельних запитів. Помилка вкладеної секції впливає лише на цю секцію мережі; помилка топології не впливає на peer-стани.

Connected routing peers враховує лише routers, прив'язані до конкретного ID підключеного peer-пристрою. Групові routers виключені, бо API не вказує для них один конкретний peer, тому значення може бути нульовим навіть за наявності групових routers.

Після невдалого опитування сутності координатора стають недоступними, щоб не показувати старі дані як поточні. Peer-пристрій, відсутній в успішному списку, також стає недоступним. Якщо необов'язкове логічне поле відсутнє, відповідний бінарний сенсор недоступний, а не вимкнений. Некоректний або відсутній час останньої активності не дає значення. Поле підключення не перевіряє VPN-маршрути, DNS, ACL чи трафік між пристроями.

Після 10 послідовних **успішних** знімків без peer-пристрою інтеграція видаляє належні їй записи реєстру. Помилки не збільшують лічильник; повернення пристрою його скидає. Лічильник зберігається лише в пам'яті, тому перезавантаження може відкласти очищення. Якщо належність пристрою або сутностей неоднозначна, видалення блокується і з'являється повідомлення Repairs. Історія, вже записана Home Assistant Recorder, зберігається за його правилами.

## Приватність і діагностика

PAT зберігається в записі інтеграції Home Assistant і надсилається NetBird Cloud лише для читання API. Захищайте резервні копії та не передавайте PAT. Увімкнені сутності IP, hostname, DNS label, операційної системи й адреси ресурсу доступні Home Assistant Recorder та можуть потрапити в історію і резервні копії. Інтеграція не створює окремої бази. Діагностика містить лише версії, стани/класи помилок оновлення й агреговані лічильники; токенів, ID, імен, адрес, приватних URL і сирих відповідей немає.

| Симптом | Що перевірити |
| --- | --- |
| Помилка авторизації | Замініть PAT того самого облікового запису через **Reconfigure** або повторну авторизацію. |
| Недостатньо дозволів | Перевірте доступ PAT до облікового запису; HTTP 403 не означає автоматично завершення терміну дії. |
| Немає з'єднання або некоректна відповідь | Перевірте доступ до `https://api.netbird.io` і стан Cloud-сервісу. |
| Peer недоступний | Перевірте останнє успішне опитування та наявність peer у NetBird Cloud. Окремі сенсори можуть бути недоступними через відсутні поля. |
| Застарілий peer залишається | Дочекайтеся 10 успішних знімків без нього; перевірте **Налаштування > Виправлення**. |
| Підключено, але трафік не проходить | Перевірте клієнти NetBird, маршрути, DNS, політики й кінцевий пристрій. |

Щоб видалити інтеграцію, видаліть її запис у **Налаштування > Пристрої та служби > NetBird**. Потім видаліть інсталяцію HACS або каталог `custom_components/netbird` та перезапустіть Home Assistant. Непотрібний PAT відкличте окремо в NetBird. Для історії Home Assistant і резервних копій діють окремі правила зберігання.

## API та обмеження

Інтеграція читає `GET /api/accounts`, `GET /api/peers`, `GET /api/networks`, `GET /api/networks/{id}/resources` і `GET /api/networks/{id}/routers` за фіксованою Cloud-адресою. Застарілий `/api/routes` не викликається. Обов'язкові ID і поля топології перевіряються; необов'язкові peer-поля можуть бути відсутніми або `null`. Тайм-аут запиту 10 секунд. Після HTTP 429 або серверної помилки інтеграція чекає наступного опитування. NetBird [зазначає, що обробка помилок API ще у стані beta](https://docs.netbird.io/api/guides/errors); звичайний HTTP 404 не означає завершення терміну PAT. Дивіться [довідник API](https://docs.netbird.io/api). Тести використовують анонімізовані fixtures і mocked responses; hosted CI перевіряє цю реалізацію, але документація не стверджує, що для повного набору endpoint-ів v0.2.0 виконано manual live API contract validation.
